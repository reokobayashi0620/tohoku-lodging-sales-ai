# 東北リペア営業ノート（Phase 1）

東北6県の民泊・宿泊施設へ、床・建具・家具・水回りのキズ補修／コーティングを提案するための営業支援Webアプリです。

> **交換・リフォームする前に、補修という選択肢を。**
> 宿泊施設の修繕コストと稼働停止を減らす、東北の現地メンテナンスパートナーを目指します。

## できること

- 施設・運営会社・連絡先・公開情報の出典・営業上の特徴を登録／編集
- 条件に応じた優先度（S / A / B / C）と判定理由の自動生成
- キーワード、県、優先度、営業ステータスによる検索・絞り込み
- 一覧から営業ステータスを更新
- 標準／ペット可／複数施設運営向けの営業文テンプレートを生成しコピー
- Excelでも文字化けしにくいUTF-8（BOM付き）CSV出力
- 初回起動時に架空のサンプルデータ5件を自動投入

営業文は**下書きだけ**を生成します。自動送信や大量送信は行わず、最終確認と送信は必ず人が行う設計です。スクレイピング機能もありません。公開情報を手作業で登録し、各サイトの利用規約と `robots.txt` を守ってください。

## 技術構成

| 項目 | 採用技術 | 理由 |
|---|---|---|
| Web | Python + Flask | 小規模で分かりやすく、保守するファイルが少ない |
| DB | SQLite | 無料、設定不要、1ファイルでバックアップ可能 |
| 画面 | HTML / CSS | 古いMacのブラウザでも利用しやすく、ビルド不要 |
| 配置 | Docker / Gunicorn | Render等の低コストサービスへ移行しやすい |

外部AI APIは使っていないため、APIキーも費用も不要です。秘密情報は環境変数で渡し、`.env` やDBはGitに含めません。

## クラウド公開方針：Render

このプロジェクトの公開先は **Render** に一本化します。GitHub の `main` と接続して
`render.yaml`（Blueprint）から Docker Web Service と永続ディスクをまとめて作成でき、
ブラウザだけでデプロイと運用ができます。Phase 1 の Flask + SQLite を変更せず維持でき、
将来はログイン機能や Render Postgres へ段階的に移行できます。

GitHub Pages は静的ファイル専用で Python プロセスと SQLite を実行できないため使用しません。
無料 Web Service には永続ディスクを付けられないため、データを守る本番構成では有料の
Starter Web Service を選びます。

### 費用の目安

構成は Starter Web Service 1台と 1 GB の永続ディスクです。目安は **月額 US$7.25
（Web Service US$7 + ディスク US$0.25/GB）から**です。料金・税・為替は変更されるため、
作成確定前に Render が画面に表示する月額を必ず確認してください。
[Render の料金表](https://render.com/pricing)と
[永続ディスクの説明](https://render.com/docs/disks)も参照してください。

### リポジトリに追加済みの設定

`render.yaml` は次を自動設定します。

- リポジトリの `Dockerfile` で Flask を Gunicorn 起動
- `/var/data` に 1 GB の永続ディスクをマウント
- SQLite の保存先を `/var/data/sales.db` に固定（再デプロイでも残る）
- `/healthz` を死活監視に使用
- `main` 更新時の自動デプロイ
- `SECRET_KEY` を Render 側で自動生成
- `APP_USERNAME` と `APP_PASSWORD` は初回作成画面で入力し、GitHub には保存しない
- HTTPS でのみセッションCookieを送信

## ブラウザだけで公開する手順

ここから先は **Render アカウントの作成、GitHub へのアクセス許可、支払い方法の登録、
秘密のパスワード入力**を本人が行う必要があります。第三者に代行させないでください。

1. ブラウザで [Render](https://dashboard.render.com/) を開き、`Get Started` をクリックします。
2. `GitHub` を選び、自分の GitHub アカウントで連携を許可します。
3. Render Dashboard の `New +` → `Blueprint` をクリックします。
4. このリポジトリ `tohoku-lodging-sales-ai` を選び、接続するブランチが `main` であることを確認します。
5. Blueprint 名はそのままで `Apply`（または `Deploy Blueprint`）へ進みます。
6. 秘密情報の入力欄で次を入力します。
   - `APP_USERNAME`: 自分だけが分かるユーザー名（メールアドレスでなくても可）
   - `APP_PASSWORD`: 他で使っていない長いパスワード（16文字以上を推奨）
7. 画面に Starter と 1 GB Disk の月額見積もりが表示されることを確認します。
8. 内容と料金に同意できる場合だけ、支払い方法を登録して作成を確定します。
9. デプロイが `Live` になったら、表示された `https://...onrender.com` をクリックします。
10. ブラウザの認証画面に手順6のユーザー名とパスワードを入力します。アプリの一覧が出れば完了です。

以後、GitHub の `main` にマージされた変更は自動デプロイされます。古い Mac への
Python、Docker、ターミナルツールのインストールは不要です。

### データ永続化とバックアップ

SQLite ファイルはアプリ本体とは別の `/var/data` 永続ディスクに置かれるため、通常の
再デプロイやアプリ再起動では消えません。ただし、**Render のサービスやディスクを削除すると
データも失われ得ます**。画面の「CSV出力」を定期的にクリックし、Mac または別の安全な場所に
日付付きで保管してください。CSV は営業データの控えであり、SQLite ファイルを完全復元する
仕組みではない点にも注意してください。将来、複数人利用や厳密な復旧が必要になったら、
自動バックアップのある PostgreSQL への移行を検討します。

### セキュリティ上の注意

- 公開環境では Basic 認証を有効にし、`APP_USERNAME` と `APP_PASSWORD` の両方を必ず設定します。
- パスワードやAPIキーをコード、`render.yaml`、README、Issue、コミットへ書きません。Render の
  Environment（秘密情報）だけに入力します。現在は外部AI APIを使わないためAPIキーは不要です。
- Render の HTTPS URL だけを使い、パスワードを他サイトと使い回さないでください。
- これは公開直後の最低限の単一ユーザー保護です。複数利用者、個別権限、退職者の停止、操作履歴が
  必要になる前に、Phase 2 でフォームログイン、パスワードハッシュ、CSRF対策を実装します。
- 連絡先など必要最小限の情報だけを保存し、CSVにも同じ営業情報が含まれるため安全に保管します。
- `/healthz` は監視のため認証不要ですが、営業データや秘密情報は返しません。

## ローカルで動かす場合（クラウド利用だけなら不要）

Python 3.10以上をインストール後、ターミナルでこのフォルダへ移動して以下を順番に実行します。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
flask --app app run
```

ブラウザで <http://127.0.0.1:5000> を開きます。停止はターミナルで `Control + C` です。次回は `source .venv/bin/activate` と `flask --app app run` だけで起動できます。

### データとバックアップ

データは初回起動時に `instance/sales.db` に作られます。アプリを止めた状態でこのファイルをコピーすればバックアップできます。サンプルを消す場合は画面で各レコードを実データに編集してください（Phase 1では誤操作防止のため削除機能は設けていません）。

## 優先度ルール

- **S**: 宿泊施設で、ペット可・一棟貸し・複数運営・木質床のうち3条件以上
- **A**: 宿泊施設で上記条件が1つ以上、または複数施設を運営
- **B**: その他の一般的な宿泊施設
- **C**: 非宿泊施設、または判断材料が不足

判定結果は登録・編集時に更新されます。営業担当者が理由を見て最終判断してください。
